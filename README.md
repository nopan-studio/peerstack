# peerstack

> Pi-to-Pi agent mesh with model-aware hub.

`peerstack` connects [Pi](https://github.com/mario-coding-agent/pi) coding agents into a live mesh so they can message, delegate, and collaborate autonomously. A lightweight Bun hub routes SSE messages between agents, tracks presence, and renders a live terminal dashboard.

---

## Features

- **Agent Mesh** — Message any connected Pi agent by name or session ID over SSE.
- **Broadcast & Multicast** — Send to multiple agents at once, or target entire groups (`@frontend`, `#backend`).
- **Threaded Conversations** — `reply_to` and `thread_id` keep multi-turn context intact.
- **Message Priority & Timeouts** — Urgent/high/normal/low priority; configurable await timeouts.
- **Agent Discovery** — Search peers by skill, topic, or group via the capability registry.
- **Presence & Profiles** — Agents expose description, skills, current task, availability, and group tags.
- **Live Terminal Dashboard** — Real-time hub UI showing agents, model usage, context bars, and conversation flow.
- **Pool Widget** — Every agent shows a live peer list below the editor with status, context %, and queue depth.
- **Auto-Replies** — Responses generated by an agent automatically flow back to the sender on `agent_end`.
- **Stale & TTL Management** — Heartbeat-based stale detection, message expiry, and hop-limit anti-loop protection.
- **Auth & LAN Ready** — Auto-generates tokens on localhost; set `PEERSTACK_AUTH_TOKEN` for remote/LAN use.

## Architecture

```
┌─────────────┐      SSE/HTTP       ┌─────────────────────┐
│  Pi Agent   │ ◄─────────────────► │   peerstack hub     │
│  (+ ext)    │   (prompt/response) │  (Bun + dashboard)  │
└─────────────┘                     └─────────────────────┘
       ▲                                    │
       └────────── hub_list / hub_send ─────┘
                hub_await / hub_get
                hub_status / hub_capabilities
                hub_subscribe
```

- **Hub** (`hub/server.ts`) — SSE broker, HTTP API, terminal dashboard.
- **Agent Extension** (`extensions/agent.ts`) — Hub client that registers the Pi agent and exposes mesh tools.
- **Spawn Script** (`scripts/spawn.ts`) — Launch agents from markdown definitions (`agents/*.md`).
- **Tests** (`tests/hub.test.ts`) — Bun integration tests for delivery, reconnect, and response flows.

## Installation

Requires **Bun** and the **Pi** coding agent CLI.

```bash
# 1. Clone
git clone <repo>
cd peerstack

# 2. Copy environment template
cp .env.sample .env
# → Add at least one API key (OpenAI, Anthropic, Gemini, or OpenRouter)

# 3. Make CLI executable
chmod +x stak
```

## Quick Start

### 1. Start the hub

```bash
./stak hub
# or
bun hub/server.ts
```

The hub prints its URL and auto-generates an auth token (localhost only). Set `PEERSTACK_AUTH_TOKEN` manually for LAN/remote binding.

### 2. Spawn agents

In separate terminals:

```bash
./stak spawn planner
./stak spawn builder
./stak spawn reviewer
```

Or list available agents:

```bash
./stak list
```

Agents are defined in `agents/<name>.md` with YAML frontmatter (`name`, `model`, `color`, `description`, `tools`). You can override on the fly:

```bash
./stak spawn builder --model google/gemini-3-flash-preview
```

### One-command team start

```bash
./stak team
```

Spawns the hub + all agents from `agents/*.md` in a tmux session (`peerstack-team`).
Attach with: `tmux attach -t peerstack-team`

### 3. Let agents talk

Agents can use these tools automatically:

| Tool | Purpose |
|------|---------|
| `hub_list` | List all connected agents |
| `hub_send` | Send a prompt to a peer or group |
| `hub_await` | Block until a reply arrives (with optional timeout) |
| `hub_get` | Poll for a reply non-blocking |
| `hub_status` | Show/update your profile & availability |
| `hub_capabilities` | Search agents by skill, topic, or group |
| `hub_subscribe` | Subscribe to presence events |

Example inside an agent session:

```
>>> MESSAGE FROM PLANNER <<<

Please review the auth module.

(Your response will be automatically sent back to planner.)
```

Or an agent can actively delegate:

```
Use hub_send to ask builder to generate the API client, then hub_await for the result.
```

## Environment Variables

| Variable | Default | Description |
|----------|---------|-------------|
| `PEERSTACK_HOST` | `127.0.0.1` | Hub bind address |
| `PEERSTACK_PORT` | `52965` | Hub port (`0` = OS-assigned) |
| `PEERSTACK_AUTH_TOKEN` | *(auto)* | Bearer token for `/v1/*` routes |
| `PEERSTACK_SERVER_URL` | *(auto from `~/.pi/peerstack/server.json`)* | Hub URL override for agents (use for remote/LAN) |
| `PEERSTACK_MAX_HOPS` | `5` | Circular-routing prevention |
| `PEERSTACK_MESSAGE_TTL_MS` | `1800000` | Message expiry (30 min) |
| `PEERSTACK_MAX_INBOX` | `100` | Per-agent inbox depth limit |
| `PEERSTACK_HEARTBEAT_MS` | `10000` | Agent heartbeat interval |

## API Endpoints (v1)

All routes under `/v1/` require `Authorization: Bearer <token>` when auth is enabled.

| Method | Endpoint | Description |
|--------|----------|-------------|
| `GET` | `/health` | Hub health & uptime |
| `POST` | `/v1/agents/register` | Register / update agent |
| `GET` | `/v1/events?session_id=` | SSE stream for inbound messages |
| `GET` | `/v1/agents` | List all agents |
| `DELETE`| `/v1/agents/:sid` | Disconnect agent |
| `POST` | `/v1/agents/:sid/heartbeat` | Heartbeat + profile update |
| `POST` | `/v1/messages` | Send message(s) |
| `GET` | `/v1/messages/:msg_id` | Get message / broadcast aggregate |
| `POST` | `/v1/messages/:msg_id/response` | Submit reply |
| `POST` | `/v1/messages/:msg_id/read` | Mark as read |
| `GET` | `/v1/capabilities?skill=&topic=&group=` | Search agent directory |
| `POST` | `/v1/subscriptions` | Subscribe to presence events |
| `DELETE`| `/v1/subscriptions?subscription_id=` | Unsubscribe |
